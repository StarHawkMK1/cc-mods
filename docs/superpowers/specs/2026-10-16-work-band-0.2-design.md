# work-band 0.2 설계

- 작성일: 2026-10-16
- 상태: 사용자 검토 대기
- 기반: `2026-10-15-work-band-design.md`(0.1.0). 이 문서는 0.1에서 바뀌거나 더해지는 것만 적는다. 적지 않은 규칙은 0.1 그대로다.
- 기준 환경: Claude Code 2.1.301, Windows 11, Git Bash

## 1. 목적

work-band 0.1.0에 네 가지를 더한다.

1. **다른 스킬 표시:** superpowers가 아닌 스킬(taste-skill, frontend-design, emil-design-eng, impeccable, docs-system, vault 등)이 돌 때 막대에 스킬 이름과 진행을 보여 준다.
2. **`--resume` 흐름 복원:** 세션을 다시 열면 superpowers 흐름과 끝나지 않은 할 일 목록이 돌아온다.
3. **TDD 빨강/초록 칩:** 가장 최근 테스트 실행의 통과·실패를 보여 준다.
4. **요청 경과 시간:** 이번 요청이 시작된 뒤 흐른 시간을 보여 준다.

## 3. 범위 밖

- 스킬별 단계 인식(스킬마다 단계표를 두는 방식)
- 테스트 통과·실패 개수 표시
- 패널에 서브에이전트별 테스트 결과
- resume 때 서브에이전트 기록, 패널, 경과 시간 복원
- 이전 세션에서 ✕로 지운 흐름 기억하기(기록에 남지 않으므로 resume 때 다시 나타난다)

## 4. 0.1에서 바뀌는 규칙

**슬래시로 부른 스킬도 새 요청이다.** 0.1은 슬래시 커맨드를 새 요청으로 치지 않았다(0.1 §7). 그런데 대상 스킬은 대부분 슬래시로 부르므로, 그대로 두면 `/impeccable`을 입력해도 경과 시간이 이전 요청의 멈춘 값으로 남고, 이전 요청의 끝난 할 일 목록과 스킬 이름도 남는다.

- 바뀐 규칙: 실행 중인 턴이 없을 때 사용자가 보낸(`origin.kind`가 `composer`·`bridge`·`sdk`) 슬래시 커맨드가 §7.1의 방법으로 **스킬로 확정되면** 새 요청이다. superpowers 스킬도 같다.
- `/model`, `/clear`, `/work-band`처럼 스킬이 아닌 커맨드는 여전히 새 요청이 아니다.
- 순서: 확정되면 먼저 새 요청 처리(0.1 §7 표의 "새 요청" 행)를 하고, 그다음 스킬 신호를 적용한다. 거꾸로 하면 새 요청 처리가 방금 적은 스킬을 지운다.
- Finish 단계에서 사용자가 답을 슬래시 스킬로 보내도 0.1과 같이 "답"으로 친다(`hasReply`).

## 5. 막대 한 줄

```
● 제목   [막대 ··· 알약 ···]   NN%   ✓ tests   2:13   ▣ ×N   ✕
```

| 요소 | 내용 |
|---|---|
| 테스트 칩 | §8. 결과가 없으면 그리지 않는다. 실패 `✗ tests`(빨강), 통과 `✓ tests`(초록). 한국어는 `테스트` |
| 경과 시간 | §6. 패널과 같은 `fmtTime` 형식(`0:13`, `2:13`, `1:02:13`). 재는 중에는 흐리게, 멈추면 보통 색 |

- 데스크톱은 0.1처럼 SVG 한 장에 그리고, 두 요소를 대체 텍스트에도 넣는다.
- 터미널은 `NN%` 뒤에 `Text`로 붙인다. 폭이 모자라면 경과 시간부터 뺀다.
- 막대가 없으면 칩과 시간도 없다.

### 막대 우선순위 (`pickBar`)

1. superpowers 흐름
2. ✕로 숨긴 상태면 없음
3. **스킬 막대**(§7): 이번 요청의 스킬이 있을 때
4. 메인 할 일 목록
5. 이번 요청의 서브에이전트
6. 없음

## 6. 경과 시간

- 상태 `clock?: { from: number; to?: number }`.
- **시작:** 새 요청(0.1 §7, 그리고 §4의 슬래시 스킬)에서 `{ from: 지금 }`.
- **멈춤:** 그 뒤 처음 오는 메인 `turn.complete`에서 `to: 지금`. 이유(`answer`, 오류, 중단)는 따지지 않는다. 이미 `to`가 있으면 그대로 둔다. 끝난 백그라운드 작업 알림으로 턴이 다시 돌아도 시간이 늘지 않게 하려는 것이다.
- **표시:** `clock`이 있을 때만. 값은 `(to ?? now) − from`.
- **타이머:** 0.1의 1초 타이머는 실행 중인 서브에이전트가 있을 때만 `now`를 갱신한다. `clock`이 있고 `to`가 없을 때도 갱신하도록 넓힌다.
- resume 재생은 `clock`을 만들지 않는다. 다음 새 요청 전까지 시간은 보이지 않는다.

## 7. 스킬 막대

### 7.1 신호

| 누가 불렀나 | 잡는 곳 |
|---|---|
| 모델 | `tool.call { tool: 'Skill' }`에서 `e.agentId`가 없고 정상 응답한 호출의 `e.skill`, `e.args` |
| 사용자의 슬래시 | `prompt.submit`의 `e.command`(또는 `command.run`의 `e.command`)를 **후보**로 적어 둔다(실행 중인 턴이 없고 사용자 출처일 때만). 곧이어 `skill.prompt`가 같은 이름으로 오면 확정한다 |

- `skill.prompt`는 스킬이 펼쳐질 때만 일어난다. 내장 커맨드와 플러그인 커맨드는 일으키지 않으므로 확정 단계에서 걸러진다.
- `skill.prompt`에는 `agentId`가 없다. 서브에이전트가 부른 스킬과 구분하려고, 후보와 짝이 맞을 때만 인정한다.
- 후보는 확정되면 지우고, 메인 `turn.complete`에서도 지운다. 지난 후보가 나중에 엉뚱하게 확정되지 않게 하려는 것이다.
- 확정된 superpowers 스킬은 0.1의 흐름 신호로 쓰고 스킬 막대는 만들지 않는다. 0.1에서 `prompt.submit`/`command.run`이 바로 흐름을 움직이던 것은 이 확정 경로로 옮긴다.

### 7.2 규칙

- **대상:** 이름이 `superpowers:`로 시작하지 않는 스킬이면서 필터를 통과한 것.
- **필터 `skills`:** 쉼표로 구분한 목록, 앞뒤 공백 무시, 대소문자 무시. 항목이 `:`로 끝나면 접두어로 맞추고(`taste-skill:`), 아니면 이름 전체가 같아야 한다(`impeccable`, `docs-system:wrapup`). 비어 있으면 모두 대상이다.
- **상태:** `skill?: { name: string; args?: string }`. 이번 요청에서 마지막으로 확정된 대상 스킬. 새 요청 때 지운다.
- **흐름이 있으면:** 흐름이 이긴다. 스킬 막대는 그리지 않는다(상태는 적어 둔다).
- **제목:** 스킬 이름. `x:x`처럼 앞뒤가 같으면 `x` 하나만.
- **알약과 채움:**

| 데이터 | 알약 | 채움, 끝남 |
|---|---|---|
| 메인 할 일 목록 | `Tasks 2/5`, 다 끝나면 `Done` | 0.1 할 일 막대와 같다 |
| 이번 요청의 서브에이전트 | `Agents 1/3`, 다 끝나면 `Done` | 0.1 에이전트 막대와 같다 |
| 둘 다 없음 | `clock.to`가 없으면 `Running`(`실행 중`), 있으면 `Done` | 0, 끝나면 1 |

- **대체 텍스트:** 스킬 이름, 알약, 인자 첫 줄, 현재 할 일.
- **✕:** 하네스 막대처럼 숨긴다. 새 할 일, 새 서브에이전트, 새 스킬이 오면 다시 보인다.

## 8. 테스트 칩

### 8.1 대상

`tool.call { tool: 'Bash' }`. 메인과 서브에이전트 모두. 다음은 반영하지 않는다.

- 훅이 거부한 호출(`deny`)
- 입력 `run_in_background`, 결과 `backgroundTaskId`가 있는 것
- 결과 `interrupted`, `timedOutAfterMs`가 있는 것

### 8.2 테스트 명령인지

1. 명령을 `&&`, `||`, `;`, `|`로 조각낸다(각 구분자를 기억한다).
2. 각 조각의 앞에서 `cd <경로>`, `VAR=값`(여럿), 실행기(`npx`, `bunx`, `pnpm exec`, `pnpm dlx`, `uv run`, `poetry run`, `bundle exec`)를 뗀다.
3. 아래 접두어 또는 설정 `testCommands`의 접두어로 시작하는 조각이 있으면 테스트 실행이다. 접두어는 단어 단위로 맞춘다(`go test`는 `go testing`과 맞지 않는다).

```
npm test | npm run test | npm t | pnpm test | pnpm run test | yarn test | bun test | bun run test
vitest | jest | mocha | playwright test | deno test
pytest | python -m pytest | python3 -m pytest | py.test | tox
cargo test | cargo nextest | go test | dotnet test | swift test | ctest | make test
mvn test | gradle test | ./gradlew test | rspec | rake test | phpunit | mix test
claude plugin test
```

### 8.3 통과·실패

- **종료 코드를 믿는 경우:** 마지막 테스트 조각 뒤에 `&&`만 오거나 아무것도 오지 않을 때. 결과가 오류(`isError`)면 실패, 아니면 통과.
- **출력으로 판정하는 경우:** 그 뒤에 `|`, `;`, `||` 중 하나라도 오면(`… | tail`, `…; echo done`, `… || true`) 종료 코드가 테스트의 것이 아니다. `stdout`과 `stderr`를 합쳐서 본다.
  - 실패: 1 이상의 `N failed`·`N failing`·`N failures`·`N fail`, 또는 줄 머리의 `FAIL`·`FAILED`·`--- FAIL:`, 또는 `Tests failed`.
  - 통과: 실패 표시가 없고 `N passed`·`N pass`·`ok `(줄 머리, go)·`Tests passed`·`0 failed`가 있다.
  - 둘 다 없으면 반영하지 않는다.
- 판정한 순간의 결과로 상태 `test?: { isPass: boolean; at: number }`를 바꾼다.

### 8.4 언제 지우나

| 상황 | 테스트 칩 |
|---|---|
| 새 요청 | 진행 중인 superpowers 흐름이 있으면 유지, 아니면 지운다 |
| 새 흐름 시작(`brainstorming`, 또는 흐름이 없을 때 다른 단계 스킬) | 지운다 |
| ✕ | 지운다 |

## 9. resume 재생

### 9.1 언제

- `session.start`(`claude --resume`·`--continue`로 프로세스가 뜰 때)와 `classic.SessionStart`(`source`가 `resume` 또는 `fork`)에서 시도한다.
- 상태 `isReplayed`가 없을 때만 한 번. 시도하는 순간 `isReplayed: true`를 쓰고, 그때의 상태 버전을 기억한다.
- `$.state`는 resume·clear·branch 때 초기화되므로 상태가 새로 생길 때마다 정확히 한 번 재생된다. hot reload 때는 상태가 남으니 재생하지 않는다.
- `/clear` 뒤나 새 세션은 기록이 비어 있어 아무것도 생기지 않는다.

### 9.2 무엇을 읽나

`$.session.messages()`(메인 대화)를 순서대로 신호로 바꾸고, 실시간 훅과 같은 함수(§10)로 접는다. 서브에이전트 기록은 읽지 않는다.

| 기록 | 신호 |
|---|---|
| 사용자 메시지 중 `<command-name>/이름</command-name>`이 있고 이름이 superpowers 단계 스킬인 것 | 새 요청, 이어서 슬래시 스킬(`<command-args>…</command-args>`가 인자) |
| `<command-name>`이 있지만 superpowers 단계 스킬이 아닌 것 | 버린다. 기록만으로는 스킬인지 내장 커맨드(`/model`)인지 알 수 없고, superpowers 외 스킬은 어차피 복원하지 않는다 |
| 그 밖의 사용자 메시지: `toolResults`가 없고 `text`가 비어 있지 않으며 `<task-notification`·`<system-reminder`·`<local-command`·`Caveat:`·`Base directory for this skill:`·`[Request interrupted`로 시작하지 않음 | 새 요청 |
| 어시스턴트의 `toolUses`: `Skill`, `Write`, `Edit`, `NotebookEdit`, `TodoWrite`, `TaskCreate`(id는 `result.task.id`), `TaskUpdate`, `Bash` | 실시간 훅과 같다. `isError`인 호출은 버린다. `Bash`는 §8로 판정한다 |
| Finish 단계에서 `hasReply` 뒤에 다음 요청이 오거나, 기록이 어시스턴트 응답으로 끝남 | 메인 턴 정상 종료(흐름 끝남) |

### 9.3 결과

- **남기는 것:** `flow`, 끝나지 않은 메인 `todos`, 흐름이 진행 중이면 `test`.
- **버리는 것:** `skill`, `clock`, 서브에이전트, `agentTodos`. `since`는 지금으로 둔다.
- 쓰기: `$.state.set(work, 결과, { ifVersion: 기억한 버전 })`. 재생하는 사이에 프롬프트나 도구 호출로 상태가 바뀌었으면 쓰지 않고 버린다. 두 훅이 함께 와도 두 번 적용되지 않는다.
- 흐름이 Build이고 작업 수를 모르며 Build 스킬 인자에 `.md` 경로가 있으면, 쓰고 난 뒤 0.1처럼 `$.fs.read`로 한 번 읽는다.
- 오류는 삼키고 막대 없이 넘어간다.

### 9.4 한계

- 기록은 최근 4096개까지다. compact 뒤에는 남은 기록만 있다. 흐름이 중간에서 시작한 것으로 보일 수 있고, 그때는 0.1의 "흐름이 없을 때 단계 스킬이 불리면 그 단계에서 시작" 규칙을 따른다.
- ✕로 지운 흐름은 다시 나타난다(§3).

| `hooks/i18n.ts` | `running`, `tests` |
| `types/index.d.ts` | `Work`에 `skill?`, `clock?`, `test?`, `isReplayed?`, 슬래시 후보 `pendingSlash?` |

실시간 훅과 재생이 같은 `events.ts`를 쓰므로 규칙이 두 곳에 갈라지지 않는다. 구조를 옮기는 첫 작업은 동작을 바꾸지 않는다(§13의 1).

## 11. 설정

| 키 | 값 | 기본 |
|---|---|---|
| `language` | `auto`, `en`, `ko` | `auto` (0.1과 같다) |
| `skills` | 쉼표로 구분한 스킬 이름·접두어 | `""`: superpowers 외 모두 |
| `testCommands` | 쉼표로 구분한 명령 접두어. 기본 목록에 더한다 | `""` |

두 목록은 `register(on, options)`가 받을 때 한 번 읽는다. 바꾼 값은 mod가 다시 로드될 때(새 세션, hot reload) 반영된다.

## 12. 확인 안 된 가정과 대안

구현 첫 작업에서 실제 세션(`--plugin-dir`, 로그만 찍는 임시 훅, 버리는 코드)으로 확인한다. 다르면 다음 작업 전에 이 문서를 고친다.

| | 가정 | 틀리면 |
|---|---|---|
| a | `claude --resume` 때 `classic.SessionStart`가 `source: resume`으로 오고, `session.start`도 온다 | 오는 쪽 하나에서만 시도한다. 둘 다 안 오면 첫 `ui.render`에서 시도한다 |
| b | 그 시점에 `$.session.messages()`가 이전 기록을 돌려준다 | 첫 `prompt.submit` 전, 첫 `ui.render`에서 시도한다 |
| c | 기록에 슬래시 스킬이 `<command-name>/이름</command-name>`으로 남고, 펼쳐진 스킬 본문은 `Base directory for this skill:`로 시작하는 별도 메시지다 | 형식이 다르면 §9.2의 걸러 내는 목록과 정규식을 실제 형식에 맞춘다. 슬래시가 아예 남지 않으면 슬래시 스킬은 복원하지 않는다(기록의 `Skill` 호출만 쓴다) |
| d | `/impeccable` 입력 때 `prompt.submit`(또는 `command.run`) 다음에 `skill.prompt`가 오고, `skill.prompt`의 `skill`은 `prompt.submit`의 `command.name`과 같은 형식이다 | 순서가 거꾸로면 가장 최근의 확정 안 된 쪽과 어느 순서로든 짝짓는다. 형식이 다르면(`wrapup` + `pluginName`) `pluginName:skill`로 맞춘다 |
| e | 0이 아닌 종료 코드로 끝난 `Bash`는 `tool.call` 결과에서 `isError`다 | 종료 코드를 믿는 경우도 §8.3의 출력 판정을 쓴다 |

## 13. 테스트

`claude plugin test ./mods/work-band`. 막대 테스트는 터미널과 데스크톱 양쪽에서 한다.

1. 구조 이동(§14의 1) 뒤 0.1의 78개 테스트가 그대로 통과한다. 그다음 §4·§7.1로 동작이 바뀌는 0.1 테스트(슬래시가 흐름을 시작하는 두 테스트)는 `skill.prompt`를 함께 일으키도록 고친다. 그 밖의 0.1 테스트는 끝까지 그대로 통과해야 한다.
2. 경과 시간: 새 요청에서 0부터 잼. 첫 메인 `turn.complete`에서 멈춤. 백그라운드 알림 턴 뒤에도 늘지 않음. 다음 요청에서 다시 잼. 슬래시 스킬 요청에서도 다시 잼. `/model`은 시계를 건드리지 않음. 재생 뒤에는 시간이 없음.
3. `testVerdict`: 기본 패턴, `cd x && npm test`, `VAR=1 pytest -q`, `npx vitest run`, `go testing`은 아님, `npm install`은 아님. `| tail` + `3 failed` → 실패, `| tail` + `78 pass 0 fail` → 통과, `; echo done` + 요약 없음 → 무시, `|| true` + `FAIL\tpkg` → 실패, 테스트 이름에 `FAIL`이 들어간 줄(줄 머리가 아님) → 실패로 보지 않음. `testCommands` 추가 접두어.
4. 테스트 칩: 서브에이전트 실행 반영. 백그라운드·중단·거부 무시. 흐름 중에는 새 요청 뒤에도 유지, 하네스에서는 지움. ✕와 새 흐름에서 지움.
5. 스킬 막대: 모델 `Skill` 호출. 슬래시 + `skill.prompt` 확정. `skill.prompt` 없이 끝난 커맨드(`/model`) 무시. 서브에이전트의 `Skill`과 짝 없는 `skill.prompt` 무시. 지난 후보는 `turn.complete` 뒤 확정되지 않음. superpowers 슬래시는 흐름으로. 필터(접두어, 정확히 일치, 대소문자, 빈 값). 할 일 → 에이전트 → `Running`/`Done` 순. 흐름이 있으면 흐름. `x:x` 제목.
6. 슬래시 스킬이 새 요청: 끝난 할 일 목록 지움, 이전 스킬 지움, 확정 뒤 스킬이 남음. Finish 단계의 슬래시 답은 `hasReply`.
7. 재생(`replay` 단위): 기록에서 Brainstorm → Spec → Plan → `Build 3/7`, 제목, 끝나지 않은 할 일 목록. `<command-name>` 슬래시 스킬. Finish 끝남. `isError` 버림. `TaskCreate` id. 테스트 칩은 흐름 중일 때만. 빈 기록, 모르는 도구, 이상한 메시지.
8. 재생(훅): 한 번만. 리로드 때는 안 함. 재생 중에 상태가 바뀌면 결과를 버림. 두 훅이 함께 와도 한 번.
9. 데스크톱 대체 텍스트에 칩과 시간, 스킬 인자 첫 줄.

마지막으로 실제 세션에서: superpowers 흐름 도중 종료 → `claude --resume`으로 같은 단계·제목·작업 수 복원, 테스트 실패 → 통과 칩, `/impeccable` 스킬 막대와 시간, `/model`은 막대를 바꾸지 않음.
